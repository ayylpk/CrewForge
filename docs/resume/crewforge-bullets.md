# CrewForge 简历素材（草稿 v1）

> 用法：**不要**写"完成了一个多 Agent 平台"。按下面三块写，每块都有一句能被追问的硬东西。
> 数字处标了 `__待填__`：跑通一次后填上（P1），否则整条的强度掉一半。

---

## 一、主条目（放项目经历首位）

**CrewForge｜可验证的 LLM 软件交付流水线**（独立设计/主导开发，TypeScript + Bun + Docker + Vue）

- 设计并实现「LLM 只负责提议、机器负责判决」的交付流水线：需求 → 可执行验收契约 → 功能竖切实现 →
  **四级执行式验证**（真实编译 / 启动 / HTTP 契约 / 渲染）→ 失败六类机器分流 → 有界返工 → 预算熔断。
  **通过结论只能由命令退出码产生**，模型在类型层面没有宣布成功的通道。
- 建立失败账本与执行式自纠闭环：同一失败签名 + 同一修法出现第二次即禁止原地重试，强制换策略；
  修复后**必须重跑验证**才允许交付。冻结场景实测：编译通过率 `__待填__`、契约测试 `__待填__`/`__待填__`、
  端到端中位耗时 `__待填__`、单项目 token 成本 `__待填__`。
- 把控制流从「数据库驱动的多 Agent 消息总线」迁移到**显式状态机 + 持久化步骤表**（SQLite、content-hash 幂等、
  租约回收）。崩溃恢复经验证：进程中途被硬杀（exit=99）后，已完成的步骤不重跑，只重跑崩溃那一步。
- 用真实编译抓住 LLM 的**幻觉 API**：隔离验证显示 3 处调用不存在的方法/构造器签名，通过了当时
  全部基于模型判断的关卡（纸审清单、正则比对、模型自置信），**只有真实 classpath 编译能发现**。
  据此重排优先级：静态校验降级为写盘前预筛，主线改为真实编译。

## 二、可讲的三个"取舍"（面试官会追这个）

1. **删掉自己写的编排层**：最初实现是"多角色 Agent 通过消息总线协作"。九轮真实运行后按日志归因发现
   瓶颈不在编排而在**验证缺失**，于是把控制流改成确定性状态机，消息总线只保留为事件流（前端展示用）。
2. **不追求"支持任意技术栈"**：确立"可自定义的边界 = 验证器的覆盖边界"——没有验证器的栈允许生成，
   但必须显式标注「未验证」，且不计入通过。宁可显示未验证，也不显示假绿灯。
3. **成本优先于炫技**：多 Agent 只在四个理由下成立（上下文隔离/并行/验证不对称/生成—选择）；
   同时落地四个降本杠杆（提示词前缀稳定化、小任务砍前置阶段、文件树快照化、工具循环预算化）。

## 三、"自我否定"的经历（这是最值钱的一段）

> 我用九轮真实运行的数据推翻了自己的架构，并留下了三次"假绿"的记录。

1. 18 个零依赖冒烟全绿，**同时真实产出为零** → 证明"测试全绿"与"产品可用"毫无关系。
2. 其中一条断言写的是 `未认识格式放行：backend/App.java` —— 把"Java 从未被检查"这个缺口
   **固化成了期望行为**。绿灯越多，越说明尺子错了。
3. 我自己统计产物时漏掉了一类编译诊断，得出"语法通过率 100%"，**差点亲手犯下正在修的那个错**。
   此后把"未知诊断默认计入并报警""未验证 ≠ 通过"写成了硬约束。

## 四、按目标岗位调措辞

| 岗位方向 | 主推 | 弱化 |
|---|---|---|
| Agent / LLM 应用平台 | 一、1 与三整段；强调"判决权不交给模型" | 前端与部署细节 |
| 后端 / 平台工程 | 一、3（状态机/租约/幂等/崩溃恢复）与 Docker 验证底座 | Agent 协作叙事 |
| 全栈 / 独立开发 | 一全段 + P1 的 demo 与录屏 | 内部设计细节 |

**一句话自我介绍（备用）**：
> 我做了一个把"AI 生成的代码"变成"可验证交付物"的流水线——因为我不信模型的自我判断，
> 只信编译器和真实接口。

## 五、必须避免的表述

- ❌ "基于 LangGraph 的多 Agent 协作开发平台" —— 会被问"这比一个人用 Claude Code 强在哪"，答不上就塌。
- ❌ "支持任意技术栈生成" —— 广度在这里是减分项。
- ❌ 把冒烟数量当成绩（"200 条断言全绿"）—— 要写**口径**（哪些是真机验证、哪些是纯函数）。
- ❌ 任何 `__待填__` 没填就投出去 —— 面试第一轮就会被问口径。
