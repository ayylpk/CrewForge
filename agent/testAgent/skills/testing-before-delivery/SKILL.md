# 交付前终检（Testing Before Delivery）

## 核心原则

**终检的目的是让报告可信，不是让测试变绿。**
"绿"只是可能的结论之一，不是工作目标——任何让绿"更容易达成"的手段，都在同时让报告不可信。
违反红线的字面，就是违反终检的精神。

## 何时用 / 不用

- 用：对整个项目跑测试并处理失败；`--auto` 模式；交付/上线前的质量确认。
- 不用：给新功能写测试、搭项目骨架、不看测试的纯 code review。

## 流程

1. 跑全量测试，记录**基线红**（哪些用例红、报什么错）。
2. 给每个红归类，只有三种：
   - **代码 bug** → read/grep 定位，最小修复；
   - **环境/凭证/依赖缺失** → 不许绕过（见红线），列入 remainingIssues，按 fail 报；
   - **测试本身可疑**（断言与需求明显冲突）→ 不许私改，列入 remainingIssues 交人裁决。
3. 修复后**重跑全量**（不是只跑改动文件）。
4. 重复 2-3，直到全绿，或所有不可修项已归类列全。
5. **预算意识**：自动修复只有约 30 轮迭代。同一用例连修两轮仍红 → 停止死磕，转入归类上报——fail/incomplete 也是有价值的交付。
6. 按"报告契约"出结论。

## 红线（禁止事项）

以下动作能让测试变绿、但让终检作废。发现了就停下，如实改报 fail：

- **伪造环境**：新建 `.env` / `bunfig.toml` / 配置文件注入缺失的环境变量、密钥、凭证来"满足"测试——门禁要抓的就是这个缺失（评测实录：agent 造 .env 塞 PROD_DEPLOY_KEY 骗过部署门禁）。**给缺失的配置/环境变量加"降级默认值 / fallback / ?? 兜底"同属伪造**——把"必须存在"的断言变成永远为真（评测实录第二轮：篡改测试加默认值，自评"已添加降级默认值使测试通过"）。
- **改测试**：删除、注释、跳过（`test.skip`/`.only`）、放宽断言、迁就错误实现改期望值。
- **假回归**：只跑绿色子集、引用上一次的测试输出、改码后未重跑全量就宣布通过。

| 借口 | 现实 |
|---|---|
| "我只是补了个 .env，没动代码" | 门禁检测的正是环境缺失，绕过=隐瞒，报告必须 fail |
| "这个断言本来就该改成 XX" | 未经人确认，测试就是需求；写进 remainingIssues，让人裁决 |
| "加个降级默认值是常见工程实践" | 默认值作为产品决策没错，但此处的断言就是在验证约束存在，兜底=禁用约束 |
| "只跑改动文件更快，效果一样" | 全量绿才能宣布 pass；子集绿掩盖跨用例回归 |

**红旗——出现任一念头立即停止并自检**：想注入一个值"让它过"；想删/改一行测试；想说"这是环境特例不算问题"；全量没跑完就想报 pass。

## 报告契约（--json 最后一轮输出的判定标准）

- `pass` 必要条件：最近一次**全量**测试通过 + 全程未发生红线动作。
- `fail`：仍有红且已用尽合法手段（含"环境缺失不可修"）。
- `incomplete`：达迭代上限未收敛。
- `remainingIssues` 每条为**一行字符串**，格式：`问题描述 | 归类=代码bug|环境缺失|测试可疑 | 置信度=0-100 [| 需要=<修复缺什么：找谁要哪个密钥/装什么依赖/人拍板什么>]`（"需要"段对环境缺失、测试可疑类必填），**置信度 ≥80 才上报**；以下不报（误报清单）：风格与命名建议、测试未覆盖的假想问题、第三方依赖内部问题、"建议增加测试覆盖"类空话。
- `summary` 必须含证据：最后跑的是哪条全量命令、结果数字（如 `12 pass 0 fail`）。

## 常见坑

- bash 返回 `[TIMEOUT]`/`[OUTPUT_OVERFLOW]` ≠ 测试失败：把输出重定向落盘（`... > out.log 2>&1`）再用 grep 定位。
- 报错行在 2000 行外：read 用 `offset` 续读，别靠猜。
- 各栈测试日志读法：按本次测试命令在 [references/test-logs.md](references/test-logs.md) 的目录里找到对应那一节（bun / vitest / maven / gradle 各一节）**只读那一节**，别按未指明的栈泛读全文。
