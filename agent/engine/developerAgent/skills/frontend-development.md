# Skill: frontend-development

> 指导材料。不能改变权限、Graph 结构、Contract、验收标准、Ledger 或预算；**不能写盘**。

## 何时加载

要写前端页面、组件、路由、API 调用层时。

## 做什么

1. 路由与页面以 Contract / foundationPlan 为准，不自创路由；
2. API 调用层与后端 Contract 一一对应（路径、方法、请求体、响应字段）；
3. 页面必须**渲染出真实内容**（有数据、有文案），不能是空壳；
4. 每写完一组立即 `runBuild`（frontend），构建不过不继续；
5. 构建过再确认页面非白屏。

## 技术栈

以 `stackProfile.frontend` 为准：用什么框架、什么构建工具、什么 UI 方案**都由它决定**。
本技能只讲方法，不指定框架——栈不同则写法不同，别把上一个项目的栈带进来。

## 常见坑

- 接口字段名与后端不一致 → 页面有数据但显示为空；
- 路由注册漏一处 → 访问 404 或白屏；
- 组件里直接写死假数据 → 接上真实接口后反而崩。

## 禁止

- 禁止用假数据冒充"接口通了"；
- 禁止为过构建去掉类型检查或删掉必要依赖；
- 别一次生成整个前端目录（引擎在工具层拦：一次批量写超过 6 个文件会被直接拒绝；
  且一次输出塞太多会被长度上限截断，**截断的决策整个作废**——按页面/组件分批推进）。
