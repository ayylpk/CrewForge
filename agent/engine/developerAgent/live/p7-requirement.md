# 项目需求：团队任务管理系统（team-tasks 后端）

## 背景

我们是一个 5~10 人的小团队，项目和任务现在散在聊天记录和表格里，缺一个统一的登记处。
我要的是一个后端服务：先把"谁能看见什么、谁能改什么"的规矩定死，界面以后再说。

## 目标

做一个多用户、多项目的团队任务管理服务，**纯后端 API 交付**：
用户和项目是基础，成员关系决定权限，任务挂在项目下、可打标签、可评论，
并提供项目内的任务状态汇总。

## 技术与运行约束

- 技术栈：Node + Express + SQLite（单机文件库，不引入 MySQL / Redis 等外部服务）；
- 接口风格：REST + JSON，统一 `/api` 前缀；
- 状态码约定：创建成功 201，成功 200，参数/引用错误 400，不存在 404，
  无权限 403，未认证 401；
- 服务启动：`node` 一键启动（不需要额外守护进程），监听端口读环境变量 `PORT`；
- 数据文件：SQLite 数据库文件固定放在 `backend/data/` 下（文件名自定），
  便于随时清空重来；
- 身份机制：所有请求用请求头 `X-User-Id: <用户id>` 表示"当前用户是谁"。
  **不做登录、密码、token、会话**——身份就是这一个头，服务端只做校验和权限判定。

## 数据实体与关系

1. **user 用户**：id、名称、创建时间；系统里的一切"人"都来自这张表。
2. **project 项目**：id、名称、描述、是否私密（is_private）、owner（创建者）、创建时间。
3. **membership 项目成员**：项目 × 用户的关系表；创建项目时创建者自动成为成员。
4. **task 任务**：id、所属项目、标题、描述、状态（todo / doing / done）、
   可选指派人（assignee，指向一个用户）、创建时间。
5. **tag 标签**：id、所属项目、名称；**同一项目内标签名不允许重复**。
6. **task_tag 任务-标签**：任务 × 标签的多对多关系。
7. **comment 评论**：id、所属任务、作者（当前用户）、正文、创建时间。

关系汇总：一个项目有多个成员、多个任务、多个标签；一个任务属于一个项目、
可被指派给一个成员、可打多个标签、有多条评论；一个标签可贴在多个任务上。

## 功能清单

### 用户
- 创建用户（给出名称即可）；
- 列出用户；查看单个用户详情。

### 项目
- 创建项目：名称、描述、是否私密；创建者即 owner，并自动成为成员；
- 列出项目：**只列出当前用户可见的**——自己参与的（是成员的）项目；
- 查看项目详情：带权限判定（见"权限规则"）；
- 更新项目（名称/描述/是否私密）：仅 owner 可做（非 owner 403）；
- 删除项目：仅 owner 可做；删除后项目下的任务、成员关系、标签一并清理。

### 成员
- 添加成员：仅 owner 可做；**已在项目里的用户重复添加要拒绝（400）**；
- 移除成员：仅 owner 可做；**owner 自己不能被移除**；
- 列出项目成员。

### 任务
- 在项目下创建任务：标题必填；描述可选；状态缺省 todo；可选指派给某个成员——
  **指派对象必须是该项目成员，否则拒绝（400）**；
- 列出任务：支持按项目、按状态、按指派人过滤；
- 查看任务详情；
- 更新任务：可改标题、描述、状态、指派人（指派校验同上）；
- 删除任务。

### 标签
- 在项目内创建标签：**同项目内名称唯一，重复创建要拒绝（400）**；
- 列出项目标签；删除标签（删除后任务上的关联一并移除）。

### 任务-标签
- 给任务打标签：标签与任务必须属于同一项目；重复打同一标签要拒绝（400）；
- 去掉任务上的某个标签；
- 按标签过滤任务（并入"列出任务"的过滤条件）。

### 评论
- 给任务加评论：作者 = 当前用户；
- 列出某任务的评论；
- 删除评论：**仅作者本人可删**（owner 或项目成员也不行）。

### 统计
- 项目任务汇总：给出该项目里 todo / doing / done 各有多少条，数字必须精确；
- 汇总的计数范围要与"该项目下所有任务"一致（含被指派、被打了标签的任务）。

## 权限规则（本需求的核心，验收重点）

1. **身份校验**：请求头 `X-User-Id` 缺失、或指向不存在的用户 → **401**（未认证）；
2. **私密项目**：`is_private = true` 的项目仅成员可见——非成员读项目详情、
   读项目下的任务/标签/成员/评论，必须 **403**；公开项目所有用户可读，
   但**写操作仍限成员**（创建任务、打标签、评论等，非成员 403）；
3. **成员管理**：只有 owner 能添加/移除成员，其他人（包括已是成员的用户）
   操作必须 **403**；
4. **owner 不可移除**：任何情况下 owner 不能被移出自己的项目；
5. 权限判定以"**当前请求的 X-User-Id**"为准——不能信任请求体或查询参数里
   自称的身份。

## 验收期望

这条服务最终要"被真数据证明是对的"，请按下面的标准交付：

- **从空库开始**：验收会先清空 `backend/data/` 再从零造数据，任何依赖历史数据的
  接口都不算数；造数据的过程也全走 API，不直接写库；
- **筛选必须真过滤**：按状态、按标签、按指派人过滤的接口，返回结果里
  **不允许混入不符合条件的数据**（造出多种状态/多个人/多个标签的任务，再逐一核对）；
  过滤条件组合时同样成立；
- **权限必须用不同身份实测**：验收会用多个不同的 `X-User-Id` 分别发请求，
  非成员 403、非 owner 403、owner 不可移除、加成员重复 400，这些都必须真实生效；
- **汇总必须精确**：统计接口的数字要与造出的数据逐一对得上（不是"大概"）；
- **服务可用性**：`node` 一键启动、端口读 `PORT`；启动后核心接口真实可调，
  返回体结构清晰（能直接机器解析）。

## 边界（本期不做）

- 不做登录/注册/密码/token/会话——身份就是 `X-User-Id` 头；
- 不做前端页面；
- 不做分页（数据量小，全量返回即可）；
- 不做通知、消息、附件、审计日志；
- 不引入复杂中间件；用不用 ORM 由你定（轻量优先），但不许加外部队列/缓存/搜索引擎。
