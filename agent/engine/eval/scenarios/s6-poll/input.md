# 项目需求：团队投票决策平台（quick-poll，中型全栈项目）

> 冻结输入。技术选型、UI 框架、配色布局由你决定——
> 交付约束：前后端都要能用 npm 一键安装/启动/构建（Node 生态）。

## 目标

给团队做一个轻量投票工具：有人发起一个议题和几个选项，大家在截止时间前投票，
实时看票数和百分比，截止（或发起人提前关闭）后出最终结果。前后端 + 数据库齐全。

## 功能清单

1. **发起投票**：标题、2~6 个选项文本、截止时间（ISO 日期时间）、是否匿名；
   截止时间必须晚于创建时刻，非法返回 400；选项数量不在 2~6 返回 400；
2. **投票**：投票人用姓名字符串（无登录），指定投给哪个选项（按选项文本匹配）；
   - 同一姓名在同一投票下重复投票 → **409**；
   - 投票已截止/已关闭 → **409**；
   - 选项文本在投票里不存在 → 404；
   - 匿名投票不记录投票人姓名与具体选择的对应关系，非匿名记录（供结果页展示）；
3. **实时结果**：返回总票数、每个选项的票数与百分比（保留一位小数）；
   非匿名投票附带每票明细（投票人 + 选项）；匿名投票在截止/关闭前**只有汇总**，
   截止/关闭后才附明细；
4. **关闭投票**：仅发起人能关闭（请求里带创建时填写的发起人姓名，不符 → 403）；
   关闭后不可再投，明细立即揭榜（匿名也是）；
5. **投票广场**：列表分「进行中 / 已结束」两组，进行中的带剩余时间。

## 接口约定

- REST + JSON，前缀 `/api`；资源至少包含 `/api/polls`、`/api/polls/{id}/vote`、
  `/api/polls/{id}/results`、`/api/polls/{id}/close`；
- 成功 200/201；参数非法 400；投票/投票项不存在 404；重复投票、已截止/关闭、
  非发起人关闭 → 403/409（按上面功能清单的语义）；
- 无登录系统：发起人与投票人都是姓名字符串。

## 前端页面

- 三个页面：**投票广场**（进行中/已结束两组列表 + 剩余时间）、**投票详情**
  （选项卡 + 进度条式结果条形图 + 百分比 + 非匿名的明细列表 + 截止倒计时）、
  **发起投票**（动态增减选项的表单）；
- **视觉要求**：走"活泼的决策工具"氛围——彩色选项标签、结果条形图带百分比、
  进行中的投票有倒计时提示；布局配色自成一体，
  **不许复用前两轮的样子**（单卡片清单风、朴素后台风都不要）；
- 所有后端调用走 `/api` 前缀；API 不可达时页面骨架仍能渲染，不许白屏。

## 报文与验收前置约定（供机器验收比对，字段名照此实现）

- 创建投票：`POST /api/polls`，请求体
  `{"title":"午饭吃什么","options":["火锅","轻食"],"deadline":"2030-01-01T00:00:00","anonymous":false,"creator":"验收员"}`
  → 201，响应体含自增数字 `id`；
- 投票：`POST /api/polls/1/vote`，请求体 `{"voter":"验证员A","choice":"火锅"}` → 201；
  同名再投 → 409；
- 结果：`GET /api/polls/1/results` → 200，含 `total`（数字）与选项统计；
- 关闭：`POST /api/polls/1/close`，请求体 `{"creator":"验收员"}` → 200；
  关闭后再投 → 409；
- 验收从**空库**开始、造数据全走 API：首个创建的投票 `id` 为 1，选项按创建时的
  文本顺序引用（投票按 `choice` 文本匹配，不依赖内部选项 id）。

## 验收期望（必须真实可执行）

- 上述接口按真实调用验证：创建 201、首投 201、**重复投票 409**、关闭后投票 409、
  结果里的 total 与百分比和造的数据逐一对得上；
- 前端 `npm run build` 成功；后端 `npm start` 一键启动、监听 `PORT` 环境变量；
- 首屏渲染非白屏，页面文本包含「投票」。

## 边界（本期不做）

- 不做登录/注册/账号体系；不做实时推送（前端轮询即可）；不做多语言；
- 不引入外部服务，数据库用嵌入式的即可；最小时间粒度到分钟。
