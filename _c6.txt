feat(权限): 写入时挡住"宽规则盖住窄规则" + 危险 allow

## 起因

用户问"shadowedRuleDetection 复杂吗"。读了三家的现成实现（Claude Code 的 210 行，
核心判定约 20 行），它的判据硬要求"整工具级规则"（`ruleContent === undefined`），
而我们的形态是**宽 allow 盖住窄 deny**（`Bash(git:*)` 在 policy 层盖住 `Bash(git push:*)`），
照抄一条都报不出来。

顺着这个问题往下查，发现后端判定里**没有硬拒名单**（只有 `testAgent` 本地那套有），
而剥离逻辑只认"等于任意代码执行"的前缀（解释器 / shell / 包运行器 / 下载器）——
**`npm`、`git` 这种裸命令名不在名单里**。于是：

```
policy 层：Bash(git:*)  allow        ← 合法、不被剥离
project 层：Bash(git push:*) deny    ← 想拦住推远端
判定：按来源优先级 → policy 的 allow 先命中 → git push 被放行 → 那条 deny 形同虚设
```

这不是"多问你几次"那种烦人，是**该拦的没拦**。

## 做法：挡在入库之前，而不是事后检测

事后检测只能告诉你"这条永远不会生效"，问题照样存在、还得自己去删。
写入时挡掉则遮蔽**根本不会产生**——防住永远比解释已经坏了的东西便宜。

`PermissionRuleServiceImpl.upsert` 里加两道校验（只在"新增/启用一条 allow"时生效）：

1. **危险 allow 直接拒**：复用判定期就有的 `isDangerousAllow`，并给出收窄建议
   （"请写 `python manage.py:*` 而不是 `python:*`"）。
   注意两道都要留：判定期的剥离是**已存在数据的兜底**（库里可能早就有、或从别处写进），
   写入期是**不再产生新的**。
2. **会盖住既有 deny 的 allow 拒绝**，判据两条同时成立：
   - **优先级不低于**：`rank(allow) <= rank(deny)`。更低则不构成遮蔽（它排在 deny 后面，
     永远轮不到命中）。等于也拦 —— 同层内按 id 先后，顺序是碰运气，靠运气生效的 deny 不算 deny。
   - **模式能匹配**：拿判定用的**同一个** `matches()`，用 allow 的模式去匹配 deny 的**模式串**
     （`git:*` 能匹配 `git push:*` → 那条 deny 想拦的命令，allow 会先命中并放行）。
     用"匹配模式串"当判据的理由：判定跑的是一条条具体命令，而规则描述的是命令集合；
     要判断"A 是否吃掉 B"，在只支持前缀/通配的语法里这就是可判定且**只漏不错杀**的近似。
3. **偏严方向不拦**：更宽的 deny 盖住 allow 只是"少放行"，不拒绝（拒绝理由只留在偏松方向）。

## 实测（真接口，7 项）

```
基线：Bash(git push:*) deny @project

✓ ① policy 层 Bash(git:*) allow         → 拒：会盖住 project 层的 Bash(git push:*)
✓ ② Bash(python:*) allow               → 拒：前缀是解释器，等于放开任意代码执行
✓ ②b Bash(*) allow                     → 拒
✓ ③ policy 层 Bash(git status:*) allow → 放行（收窄了就不构成遮蔽）
✓ ④ session 层 Bash(git:*) allow       → 放行（优先级更低，排在 deny 之后，遮不到）
✓ ⑤ policy 层 Bash(git:*) deny         → 放行（偏严方向不拦）
✓ ⑥ 被拒的那几条确实没进库
```

**如实说明**：第 ⑥ 条断言我一开始写错了（拿"三条被拒的都不在库里"当判据，而其中 `git:*`
是 ④ 合法写入的，于是断言成了恒真式）。逐条核对后的真实结论是：
`python:*` 与 `*` 确实没进库（② ②b 被拒）；`git:*` 进库是 ④ 的预期行为。

## 顺带说清"要不要做 shadowedRuleDetection"

**不做**。理由：它管的是"整工具级规则遮蔽带内容的 allow"这两种形态，我们没有；
而且它输出的是**解释**（面板上标一句"这条永不生效"），问题照样在。
同一个洞察用在写入时更值 —— 这就是本提交。
