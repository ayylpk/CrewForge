# Skill: backend-development

> 指导材料。不能改变权限、Graph 结构、Contract、验收标准、Ledger 或预算；**不能写盘**。

## 何时加载

要写后端代码（路由 / 服务 / 数据访问 / 实体）时。

## 做什么

1. 先从 Contract 取下当前任务的端点：method、path、入参、返回、期望状态；
2. 按 `stackProfile` 声明的栈选分层惯例（Controller/Service/Mapper、Router/Handler/Repository、
   View/Serializer/Model……），**照着栈的惯例写**，不把别的栈的结构硬套进来；
3. 逐端点实现，**一个端点一次改动**（见"禁止"第 1 条）；
4. 字段与表名一律以 Domain Model 为准，不许自创表；
5. **接线与实现同等重要**：新建的路由文件必须确认已在应用装配处挂载，且挂载顺序是
   "认证中间件 → 业务路由"。文件写了但没挂，外部表现是整片 404，很难从报错反推回装配层；
6. 写完一组立即 `runBuild`（backend），**编译不通过不继续加功能**；
7. 编译过了再用 `runCommand` / `startProcess` + `httpRequest` 起服务验证关键端点。

## 契约一致性

- 返回结构与 Contract 对齐；
- 错误壳**只有一份**：同一形状（例如 `{error:{message}}`）贯穿所有失败路径，
  不一个 handler 一种写法；
- 状态码按契约（需求未写死时用状态码类别，不要为 200/201 之争改契约）；
- **三分语义不许混**：身份缺失或无效 → 401；身份有效但无权 → 403；目标不存在 → 404。
  私有资源对非成员该给 403 还是 404，契约写了就照做，没写才按栈惯例——不要自己另定一套；
- 不新增 Contract 之外的路由。

## 数据访问

- 查询**显式列出需要的字段**，不用"取全部列"的写法；列表接口一律带数量限制；
- 多步写入（父删子清、先建关系再落状态）**放进一个事务**，不留写了一半的中间态；
- 同一请求内同一实体只取一次：循环里逐条查改成一次批量取回 + 内存建 ID 映射；
- **权限判定收成一处矩阵**（资源可见性 × 操作 → 允许 / 403），不要在每个 handler 里各写一段判断：
  判据里出现的每一种权限组合，都要能在矩阵里找到对应行。

## 验证与自检

- 起服务后至少各验一条：正常路径、缺身份（401）、无权（403）、目标不存在（404）、非法入参（400）；
- 每条判据**独立可重放**：不依赖上一条残留的数据。需要干净起点就重建数据文件——
  测试之间的状态泄漏，会让人在"上一条为什么过、这一条为什么不过"上白烧好几轮。

## 禁止

1. **别一次生成整个后端目录**，也别"先把所有路由批量写完、最后统一验证"——按端点推进，
   每完成一个端点就让它可运行、可验证，再动下一个。
   （两道硬约束：①引擎在工具层拦——一次批量写超过 6 个文件会被直接拒绝并回灌原因；
   ②输出有长度上限——一次塞"整个模块 / w1 到 w9"会被截断，而**截断的决策整个作废**，
   那一步什么都不会发生。所以**一步只做一个端点、或 1~2 个文件**。）
2. 禁止改构建配置来绕过编译错误（把报错改没 ≠ 修好）；
3. 禁止为了让编译过快进而删掉校验、异常处理。
