# Skill: frontend-design

> 前端视觉设计指导。它只能指导页面设计，不能改变 Contract、权限、Graph、Ledger、预算或验收规则。

## 适用时机

当 Developer 新建或重塑页面、布局、组件样式、主题或交互反馈时加载。

## 开始前

先明确页面服务的对象、页面唯一主要任务和真实内容。先检查已有页面、路由、Contract 和选定的 UI 资产，再决定视觉方向。

## 设计要求

1. 使用与产品主题相符的明确配色、字体层级、间距和布局，不使用没有理由的默认模板风格。
2. 视觉重点只放在一个关键元素上，其他内容保持克制，避免装饰性渐变、光球和堆叠卡片。
3. 页面优先展示真实业务内容，不用假数据掩盖接口未完成。
4. 处理 loading、empty、error、success 和 disabled 状态。
5. 交互控件使用选定 UI 库的标准组件；**同一项目内不混用两个 UI 库**（哪个库由 stackProfile 决定）。
6. 桌面和移动宽度都要检查，不能让文本、按钮或表格溢出。
7. 提供可见键盘焦点，并尊重 `prefers-reduced-motion`。
8. 颜色不能只使用单一色相；保证正文与背景有足够对比度。

## 反模式（这些是"AI 默认脸"，出现就该改）

1. 正文/背景用**纯黑或纯灰**——改用带一点点色相的近中性色，避免死板；
2. **渐变文字**、以及把半透明磨砂（玻璃拟态）当默认装饰；
3. **卡片里再套卡片**、每段标题上顶一个大圆角图标；
4. `bounce` / `elastic` 这类**弹跳过冲缓动**（观感旧）；动效必须能被 `prefers-reduced-motion` 关掉；
5. 同级元素的**间距 / 圆角 / 字号不成体系**（同一排按钮一处 12px、一处 16px）；
6. 为"显得高级"堆砌装饰：无来由的阴影、光球、大色块渐变。

> 自检口径：一段样式如果**换到任何别的产品上都不违和**，它多半就是默认模板脸，不是为这个需求做的决定。

## 实现顺序

1. 先确认路由和数据接口。
2. 再确定页面结构和组件层级。
3. 再实现布局、字体、颜色和状态反馈。
4. 使用 `runBuild` 检查构建。
5. 使用本地服务和页面检查确认不是白屏。
6. 视觉自检做**有界的一轮**（桌面与移动宽度一起看完，不逐条反复打磨）；没有进展就停手上报，别开无限的自我 QA 循环。

## 复杂页面问题：只读 UI Reviewer

build 通过但疑似白屏、路由/组件库/接口存在交叉问题、或连续两轮看不出页面为什么不对时，
用 `delegateReadonly` + `role:"ui-reviewer"` 调只读子 Agent。口径：

1. 它只做**静态分析**（页面结构、路由登记、空壳页面、loading/empty/error/success 状态、
   UI 库混用、白屏可能性）——返回结构化建议，不写盘、不执行；
2. 它不得用静态文件推断"HTTP 已通过"，`cannotVerify` 里列的运行时问题必须回到你手里：
   起服务、`httpRequest`、看真实响应，才能下结论；
3. 它的建议采纳前先用 `readFile` 核实；改不改、怎么改、何时改，决定权在你；
4. 页面"通过"只能等外部 TestAgent 的机器证据——子 Agent 说好看≠验收。

## 禁止

- 不修改验收标准来掩盖页面问题。
- 不复制 UI 库源码。
- 不同时安装或混用多个 UI 库。
- 不把页面做成只有标题和空容器的演示壳。
- 不一次覆盖整个前端目录。
- 不把只读子 Agent 的分析结果当成页面验收或 HTTP 通路结论。
